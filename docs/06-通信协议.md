# 通信协议

## 1. LD2451 雷达串口（雷达 → 哨兵）

依据海凌科《LD2451 串口通信协议 V1.03》。默认 115200、8N1，小端。

| 字段 | 字节 | 说明 |
|---|---|---|
| 帧头 | 4 | F4 F3 F2 F1 |
| 长度 | 2 | 帧内数据长度（小端） |
| 目标数 | 1 | 0～5 |
| 报警 | 1 | 01 = 有目标靠近 |
| 每个目标 | 5 | 角度(值−0x80，单位°) / 距离(m) / 方向(01 靠近，00 远离) / 速度(km/h) / 信噪比 |
| 帧尾 | 4 | F8 F7 F6 F5 |

方向字节按协议**表 9**取值。V1.03 第 9 页示例的文字把“靠近/远离”写反了，和表 9 不一致。固件 `ld2451.h` 与 `sentinel/radar.py` 都按表 9 解析。拿到模块后请用官方 App 对照一帧原始数据；若实机与表 9 相反，再改解析。【待实机核对】

无目标时帧内数据为 `00 00`。有目标时约 100 ms 一帧，无目标约 1 s 一帧。

配置命令帧头为 `FD FC FB FA`，帧尾 `04 03 02 01`（进入配置、设置距离方向、灵敏度等），一般用官方 App 配置即可，不必在固件中发送。

> 不同固件版本可能有差异，以模块附带的协议文档为准。

## 2. ESP-NOW 数据包（锥桶之间）

定义见 `firmware/common/protocol.h`，所有结构体 `#pragma pack(1)`。

### 公共包头 PktHeader（9 字节）

| 字段 | 类型 | 说明 |
|---|---|---|
| magic | u8 | 0x5C，过滤非本系统设备 |
| version | u8 | 1 |
| type | u8 | 1 预警 / 2 心跳 / 3 配置 / 4 事件 |
| node_id | u8 | 1 哨兵；2～19 联动；20+ 工人端 |
| node_type | u8 | 1 哨兵 / 2 联动 / 3 工人 / 4 网关 |
| seq | u32 | 递增序号，用于去重 |

### AlertPkt（预警）

| 字段 | 类型 | 说明 |
|---|---|---|
| level | u8 | 0 安全 / 1 一级 / 2 二级 |
| mode | u8 | 模式位：0x01 作业中、0x02 左侧封道、0x04 雨天、0x08 夜间 |
| speed_kmh | float | 来车速度 |
| dist_m | float | 距离 |
| ttc_s | float | 碰撞时间 |
| hops | u8 | 已转发次数（≤2） |

发送策略：等级变化立即发送；预警期间每 200 ms 重发；联动锥桶收到新序号后随机退避 2～15 ms 转发一次（hops+1，达到 2 不再转发）。中继包先放入队列，由主循环发出：接收回调和主循环不在同一个任务里，直接改同一块结构体可能发出半包。联动锥桶和工人端 `LINK_LOSS_MS`（3 s）收不到预警刷新，自动回到安全状态。

预警包的 `mode` 不含“作业中”，或 `level` 为 0 时，联动锥桶和工人端都回到安全，不把上一次的危险等级留到下次开工。

**去重规则**（联动锥桶、工人端、网关都调用 `protocol.h` 的 `seqIsNew()`，Python 版见 `sentinel/dedupe.py`）：按发送者 node_id 记住上次接受的序号；同号丢弃；比上次小且相差不到 `SEQ_REORDER_WINDOW`（64）视为迟到副本丢弃；相差更多视为对方重启，接受；没见过的发送者第一包一定接受。各节点上电随机起号。工人端只对预警包去重，不转发。工人端如果不去重，解除之后迟到的二级副本会把震动重新打开。

### HeartbeatPkt（心跳，每 5 s）

batt_v（float）、mode、level、rssi（int8）。

### ConfigPkt（模式变化，连发 3 次）

mode（u8）。同一次切换的 3 个副本序号相同。联动锥桶去重后应用新模式，并转发一次（没有跳数字段，靠“每个序号只转发一次”防止循环），远处只能收到中继的锥桶也能切换模式。

### EventPkt（一次车辆通过结束时）

max_level、max_speed、min_ttc、min_dist、duration_ms。

心跳和事件包**不**经联动锥桶转发，网关需要能直接收到哨兵和各节点。

## 3. 语音串口（ASRPRO ↔ 哨兵）

9600 8N1，4 字节：`AA 55 CMD SUM`，SUM = (0xAA + 0x55 + CMD) & 0xFF。

| CMD | 含义 |
|---|---|
| 01 / 02 | 开始 / 结束作业 |
| 03 / 04 | 左侧 / 右侧封道 |
| 05 / 06 | 雨天模式 开 / 关 |
| 07 / 08 | 夜间模式 开 / 关 |
| 09 | 报告电量 |
| 0A | 哨兵本机自检（红灯 + 蜂鸣闪 3 次） |
| 81 / 82 | 哨兵回复：电量正常 / 电量不足 |

示例：开始作业 `AA 55 01 00`（0xAA+0x55+0x01 = 0x100 → 0x00）。

## 4. MQTT（网关 → 服务器）

| 主题 | 负载示例 |
|---|---|
| `cone/1/alert` | `{"level":1,"mode":1,"speed":46.5,"dist":52.3,"ttc":4.05,"seq":1024}` |
| `cone/2/heartbeat` | `{"type":2,"batt":3.92,"mode":1,"level":0,"rssi":-58}` |
| `cone/1/event` | `{"max_level":2,"max_speed":58.0,"min_ttc":2.10,"min_dist":12.0,"duration_ms":6400}` |
| `cone/1/config` | `{"mode":3}` |

## 5. REST API（服务器）

| 接口 | 说明 |
|---|---|
| `GET /api/nodes` | 所有节点状态（含 online） |
| `GET /api/alerts?minutes=10` | 最近预警数据（画曲线） |
| `GET /api/events?limit=50` | 危险接近事件 |
| `GET /api/health` | `{"ok": true}` |
| `GET /api/stats?hours=24` | 统计指标。没有事件时 `avg_speed`、`top_speed`、`min_ttc` 为 `null`，不再显示成 0 |
| `GET /api/report?hours=24` | 文字版安全报告。没有事件时说明“没有记录到车辆通过事件” |

`minutes`、`hours`、`limit` 超出范围时返回 422。MQTT 负载缺字段、不是 JSON、含非有限数或超出合理范围时只记日志，不中断订阅，也不留下半条告警。心跳里没带的电量、等级等字段不会把该节点上一次的值抹掉。

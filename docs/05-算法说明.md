# 算法说明

## 1. 处理流程

```
雷达帧(10Hz) → 目标筛选 → 选最危险目标 → 卡尔曼滤波 → TTC → 阈值(自适应) → 连续帧确认 → 预警等级
                                                                                     │
                                                                事件统计（最高车速、最小 TTC、最近距离）
```

## 2. 目标筛选

LD2451 每帧最多输出 5 个目标。保留满足以下条件的目标：

- 方向为“靠近”；
- 速度 ≥ `MIN_TRACK_SPEED`（默认 5 km/h），排除行人、风吹物；
- 距离 ≤ `MAX_TRACK_DIST`（默认 100 m）。

在剩余目标中选择 **TTC 最小** 的作为当前威胁目标。

## 3. 卡尔曼滤波

采用一维常值模型：

- 预测：P = P + Q
- 增益：K = P / (P + R)
- 更新：x = x + K(z − x)，P = (1 − K)P

默认 Q = 0.5、R = 4。R 越大曲线越平滑但响应越慢。可通过实测数据离线调参：用 `tools/radar_monitor.py --csv` 录数据，在 Python 里对比不同 Q/R 的效果。

> 进阶：可改为“距离-速度”二维卡尔曼（状态 [d, v]，d_{k+1} = d_k − v_k·Δt），用速度预测距离，抗丢帧更好，可作为论文中的改进点。

## 4. 碰撞时间（TTC）

TTC = d / (v / 3.6)，d 单位 m，v 单位 km/h。速度不超过 1 km/h 时固件与 `sentinel/algorithm.py` 都返回 99 s，避免除零。同一文件里的 `alert_level`、`update_confirm`、`Kalman1D` 与哨兵固件使用同一组默认阈值，可用 `pytest` 复现，这些阈值尚未经过外场标定。

意义：如果车辆保持当前速度不减速，多少秒后到达锥桶位置。

## 5. 分级阈值的依据

| 等级 | 默认条件 | 依据 |
|---|---|---|
| 一级 | TTC < 5 s 或 v > 1.2 × 限速 | 设计意图：给司机留出察觉、减速或变道的时间 |
| 二级 | TTC < 2.5 s | 设计意图：车辆已很近，提醒工人立即避让 |

这两个数是 `config.h` 的设计初值，本仓库**没有**引用到支持它们的驾驶员反应时间实测或规范条文。【待补充：若要在答辩中解释取值，请引用打开过的规范或文献，并写明页码】阈值应在封闭场地实测中按误报率、提前量调整，并在申报书中写明标定过程。

## 6. 自适应阈值

| 模式 | 系数 | 理由 |
|---|---|---|
| 雨天 | ×1.4 | 定性理由：湿滑路面制动距离变长（系数为初值，未标定） |
| 夜间 | ×1.2 | 定性理由：夜间视距短（系数为初值，未标定） |
| 雨天 + 夜间 | ×1.68 | 叠加 |

可扩展：加光敏电阻自动判断昼夜，加雨滴传感器自动判断雨天（作为升级点）。

## 7. 防误报

1. **连续帧确认**：升级需要连续 `CONFIRM_FRAMES` 帧（默认 3 帧 ≈ 0.3 s）。确认计数停在这个上限，避免长时间跟踪一直累加。计数满了之后，若滤波结果直接进入更高一档，不需要重新计满 3 帧。
2. **降级与解除**：一帧滤波后的结果更安全时，等级马上降下来；目标从筛选里消失后，则保持 `RELEASE_MS`（1.5 s）再回到安全并上报事件。后一种判断在主循环里按时间做（`releaseIfIdle()`），用无符号 32 位毫秒做减法，时钟回绕后仍然成立。雷达无目标时约 1 s 才出一帧、或串口线松脱完全没有帧，告警也能按时解除。解除时实时速度和距离清零，极值留在事件包里。
3. **非作业模式**：`MODE_WORKING` 未置位时只排空雷达串口，不累计确认、不打开通过事件，并立即解除已有告警。结束作业的同一轮循环会先清成安全再广播，避免工人端停在旧等级。否则结束作业前路过的车会把确认计数加满，一开始作业就跳过 3 帧确认。
4. **角度窗口**：可在雷达 App 中把检测角度设窄，只盯本车道和相邻车道。
5. **护栏/静止物体**：配合最低速度过滤排除静止和慢速目标；雷达对静止物体的实际输出【待实机核对】。

上述状态机的 Python 版本是 `sentinel/algorithm.py` 的 `ThreatTracker`，固件对应 `clearThreat()` / `processRadar()`。单帧公式仍由同文件里的 `alert_level`、`update_confirm`、`Kalman1D` 与哨兵固件对齐。

## 8. 评价指标

- **提前量**：从一级预警触发到车辆到达锥桶的时间。
- **误报率**：无危险车辆时触发预警的次数 / 总观察次数。
- **漏报率**：应触发未触发 / 应触发总数。
- **联动延迟**：哨兵触发到末端锥桶点亮的时间（用手机慢动作视频逐帧测）。

## 9. 可写进论文的拓展方向

- 基于车辆是否减速（速度下降率）判断“司机是否已注意到预警”，形成**预警有效性评价**。
- 根据历史事件数据，分析不同时段、不同限速下的危险接近频率。
- 多哨兵级联（上游 150 m、80 m 各一个），计算车辆在两点间的减速度。
